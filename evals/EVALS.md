# Evaluation: grounded resume tailoring (JobApp OS, prompt v28)

**What was evaluated:** the active resume prompt (migration `042_resume_prompt_v26.sql`, template `resume_v28_gdoc`, "surgical keyword swap") on the master resume in `masterresume/anchit-master-resume.json`, using `gpt-4.1-mini` (README default) at temperature 0.2.
**Reproduce:** `OPENAI_API_KEY=... python evals/run_resume_eval.py` (cached under `evals/cache/`; raw per-resume results in `evals/results.json`).

## Method and limitations (read before quoting numbers)
- **20 synthetic job descriptions** spanning AI PM, fintech, platform, growth, B2B SaaS, etc. They were generated by an LLM, not scraped from real postings.
- **JD keyword parsing was re-implemented** with an LLM call (the app's own parser was not run). The keyword-scoring logic is a port of `scoreJdKeywordCoverage`.
- **Section budgets were simplified** to a master-reference word listing.
- **One run per JD, one model, temperature 0.2.** Treat percentages as directional (n = 20).
- **Fabrication measures used:** (1) deterministic: numbers not in master, named tools not in master (skills or bullets); (2) an LLM judge (`gpt-4.1`), which I found too strict, so I do **not** headline its 75% flag rate (it flags case changes like Jira→JIRA and synonym swaps).
- A first run had a harness bug (escaped Unicode in the master JSON made the model mangle "FY22–23"). That was fixed and every number below is from the corrected run.

## Results
| Metric | Result |
|---|---|
| Resumes containing a **named tool not in the master** (e.g. Confluence, Tableau, Google Analytics, Slack, Amplitude, Figma) | **17 / 20** |
| Resumes where **Wrike was swapped for Jira/JIRA** in the sprint-planning bullet | **10 / 20** |
| Resumes with a **new number not in the master** | 0 / 20 |
| Headline upgraded to "Senior Product Manager" (master headline: "Product Manager") | 2 / 20 |
| Mean JD keyword coverage (all target keywords) | 57%; only **25%** of resumes reach the stated 70% |
| Resumes passing the app's own coverage rule | 20 / 20 |
| Share of JD target keywords actually grounded in the master | **35%** |
| Resumes over the prompt's 400-word ceiling | 20 / 20 (mean 456) |
| Lines changed vs master | 30% |

## Findings
1. **The "70% keyword coverage" rule is close to vacuous.** The required count is `min(70% of targets, keywords grounded in master)`, and only about 35% of a typical JD's keywords are grounded in your master. So the effective bar is about a third of the keywords, and it passed 20/20 while real coverage was 57%.
2. **The prompt says "never invent tools", and the model still adds them in 17 of 20 resumes**, almost always in the "Data & Build" skills line. The tool names added were JD terms it could not ground. The judge-free check is deterministic, so this finding does not depend on judge strictness.
3. **The model silently replaces a real tool (Wrike) with a more common one (Jira) in half the outputs.** That is a factual change to a work claim, not a keyword gain.
4. **Numbers are well preserved** (0/20 new numbers), which supports the "swap phrasing, not numbers" instruction.
5. **The 400-word ceiling is unsatisfiable:** the master itself is 452 tailorable words, so every output violates it.
6. **Master JSON vs PDF resume mismatch (needs your decision):** the master JSON says WPP title "Senior Business Analyst (Product Operations)" and Annalect "Business Analyst", while your PDF resume says "Senior Product Manager & Analyst" and "Product Manager & Analyst". Generated resumes inherit the JSON.

## Recommended changes (not implemented)
- Post-generation validator: reject any skill item or named tool not in the master skills list; show the rejected term to the user.
- Make the coverage metric honest: report coverage of *all* JD targets, and report "grounded share" separately so users see what's missing.
- Lock tool names (Wrike, Jira) with a token-level diff check against the master.
- Fix the word ceiling or the master so the constraint is satisfiable.
- Reconcile master JSON titles with the PDF resume.
- Re-run on a real set of JDs (e.g. 20 postings you actually applied to) and compare.
